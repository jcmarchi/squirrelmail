# QLi Spine

The QLi Spine is the required upfront implementation baseline for QLi Buildline.

It is not a demand to build every enterprise capability before product work. It is the minimum real structure that prevents an AI coding agent from piling features onto an undefined product shape.

## Spine rule

Before broad feature work, every project must establish the applicable spine:

- Project manifest
- Operating profile
- Foundation target level
- Foundation applicability matrix
- Foundation status file
- Deferral register
- UI shell/navigation/demo surface where UI applies
- API health/response/error pattern where API applies
- Data conventions/migration/seed posture where data applies
- ACL actor/capability/policy baseline where protected behavior applies
- Security posture where public/authenticated/sensitive surfaces apply
- Testing harness and human smoke path
- Runtime/delivery/observability/devbox baselines as applicable

## Completion rule

The Spine is complete only when the applicable parts exist in code, project state, documentation/inventories, tests/smoke paths, and evidence. A document saying the spine is planned is not completion.
